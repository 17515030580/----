# OncoFusion 前端部署说明

目标：拿到一个链接，点开就能用、能跑预测。

本文档有两条路线，**按你的情况选路线 A**：

| 路线 | 代码托管 | 跑在哪 | 链接长什么样 | 需要什么 |
|---|---|---|---|---|
| **A（推荐）** | Gitee | 你自己的服务器 | `http://你的服务器IP:8501` | 服务器 + Gitee 账号 |
| B | **必须 GitHub** | Streamlit Cloud | `https://xxx.streamlit.app` | GitHub 账号 + 本地推送 |

> ⚠️ **Streamlit Cloud 用不了 Gitee。** 官方文档明确写 *"You must authenticate through GitHub to deploy or administer an app"*，
> 且只能从 GitHub 仓库拉代码。所以走 Streamlit Cloud 就必须用 GitHub。

# 路线 A：Gitee + 你的服务器（推荐）

## A0. 为什么这条对你更好

| 优势 | 说明 |
|---|---|
| 国内访问快 | 服务器在国内，不像 Streamlit Cloud 在境外 |
| **省掉证书这道坎** | 用 `http://IP:8501` 打开，前端是 HTTP，后端也用 HTTP 即可，**不会触发浏览器的混合内容拦截** |
| 后端同机时更简单 | 前端和后端在同一台机器，后端地址填 `http://127.0.0.1:8000`（详情见 A3） |
| 完全可控 | 日志、重启、换端口都自己说了算 |

> 关于混合内容：只有当你的前端页面是 **https://** 打开时，浏览器才禁止它请求 **http://** 的后端。
> 本路线默认用 `http://IP:端口` 打开，所以**后端不需要 HTTPS**，省掉申请证书和域名解析。
> （如果你后来给前端配了域名 + HTTPS，那时后端也必须是 HTTPS。）

## A2. 服务器上部署（SSH 登录服务器后执行）

```bash
# 1) 装 git（如果没有）
sudo apt update && sudo apt install -y git

# 2) 拉代码
cd ~ && git clone https://gitee.com/你的用户名/oncofusion-frontend.git oncofusion-frontend
cd oncofusion-frontend

# 3) 一键部署（后端地址写法见下方 A3，不填也能跑）
./deploy.sh
```

也可以显式指定后端地址（脚本会自动适配容器/虚拟环境两种方式）：

```bash
BACKEND_URL=http://127.0.0.1:8000 ./deploy.sh
```

脚本会自动做这些事：装中文字体（否则报告 PDF 中文是方块）→ 检测 Docker 并优先用容器部署 →
**自动纠正容器内不可用的 `127.0.0.1` 地址** → 没有 Docker 就改用 Python 虚拟环境 →
启动服务 → 打印访问地址。

**首次执行约 3–10 分钟**（取决于要不要装依赖/构建镜像）。

## A3. 后端地址怎么填（关键）

⚠️ **最容易踩的坑**：Docker 容器里的 `127.0.0.1` 指的是**容器自己**，不是宿主机。
所以后端和前端在同一台机器上时，填什么取决于前端用哪种方式跑：

| 后端实际位置 | 前端部署方式 | `BACKEND_URL` 填什么 |
|---|---|---|
| 和前端**同一台**机器，后端跑在宿主机 | Docker（脚本默认优先） | `http://host.docker.internal:8000` |
| 和前端**同一台**机器，后端跑在宿主机 | 虚拟环境 | `http://127.0.0.1:8000` |
| 同机，后端**也在 Docker 里** | 任意 | `http://后端容器名:8000` |
| 在**另一台**机器 | 任意 | `http://那台机器的IP:8000` |
| 已配 HTTPS 域名 | 任意 | `https://api.你的域名.com` |

**`deploy.sh` 会自动处理上面这个差异**——你按直觉填 `127.0.0.1:8000` 也不会出错，
脚本检测到走 Docker 就会自动改写成 `host.docker.internal` 并打印提示。
但如果你是**手工**执行 `docker compose up`，就必须自己填对。

填错了的现象很有迷惑性：**页面正常打开、图表都在、首页好看，但一点"开始预测"就失败**，
看起来像后端挂了，其实是前端连不上它。

改地址不用重新部署，编辑服务器上的 `.env` 后执行：

```bash
# Docker 方式
docker compose up -d          # 会自动读到新的 .env

# 虚拟环境方式
pkill -f "streamlit run"      # 或 sudo systemctl restart oncofusion-frontend
nohup ./.venv/bin/streamlit run streamlit_app.py --server.address=0.0.0.0 --server.port=8501 > run.log 2>&1 &
```

## A4. 打不开？按这个顺序查（90% 是第 1 条）

1. **云控制台的「安全组 / 防火墙」有没有放行 8501 端口** ← 最常见
   （腾讯云/阿里云买的机器，默认只开 22 和 80，必须手动加规则）
2. 服务器本机防火墙：`sudo ufw allow 8501/tcp`
3. 服务在不在跑：`ss -lntp | grep 8501`
4. 本机自测：`curl http://127.0.0.1:8501/healthz`，返回 JSON 说明服务正常，问题在网络上
5. 看日志：Docker 方式 `docker compose logs --tail=80`；虚拟环境方式 `tail -80 run.log`

# 路线 B：Streamlit Cloud（需要 GitHub）

只有在你能用 GitHub 时才走这条。

## B1. 推代码到 GitHub

```bash
cd /e/python-project/dachuang/MTEGDRP_Streamlit_Frontend_9_14
git remote add origin https://github.com/你的用户名/oncofusion-frontend.git
git branch -M main
git push -u origin main
```

GitHub 已停用密码推送，需在 GitHub → Settings → Developer settings → Personal access tokens
生成 token（勾 `repo`），推送时用户名填 GitHub 用户名、密码填 token。

## B2. 在 Streamlit Cloud 部署

1. https://share.streamlit.io 用 **GitHub 账号**登录
2. **New app** → 选仓库 → Branch 填 `main` → Main file path 填 `streamlit_app.py`
3. **Advanced settings → Secrets**，粘贴：

```toml
BACKEND_URL = "https://你的后端地址"
REQUEST_TIMEOUT_SECONDS = "600"
FRONTEND_MAX_UPLOAD_MB = "25"
DEMO_MODE_ENABLED = "true"
APP_TITLE = "OncoFusion 多组学肿瘤预测系统"
```

4. **Deploy**，等 3–8 分钟，得到 `https://xxx.streamlit.app`

> 改 Secrets 后应用自动重启，不用改代码、不用重新推送。这就是本次给 `config.py` 加
> `_getenv()` 的意义——后端换地址只改这一行。

## B3. 路线 B 独有的一条硬要求

Streamlit Cloud 给的是 **https://** 地址，浏览器会**禁止**它请求 **http://** 后端：

- 后端是 `https://域名` → 正常
- 后端是 `http://IP:8000` → **页面能打开、图表都在，但一点预测就失败**（Mixed Content 被浏览器拦掉）

所以走路线 B，**后端必须配 HTTPS**（Nginx + Let's Encrypt 免费证书），并且 FastAPI 要开 CORS：

```python
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],        # 演示够用；正式环境改成前端域名
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

自查：浏览器打开 `https://你的后端/health`，能返回 JSON 且地址栏是锁头图标。

# 已知风险

### 1. PDF 报告中文变方块

Linux 服务器默认没有中文字体。`deploy.sh` 已经自动装 `fonts-noto-cjk`；Docker 的 `Dockerfile` 里也已包含。
如果你手动部署，记得自己装一次。

### 2. 图表图片版导出（设计如此，不是故障）

`requirements.txt` 里**没有** `kaleido`。原因是 kaleido 0.2.x 在部分 Windows 环境启动自带 Chromium 时
会无限挂死（不抛异常、只卡住线程），所以项目改为不依赖它。

`app/report_export.py` 里的处理是分层的：

- 优先尝试 kaleido 静态导出，且**用线程 + 10 秒超时**兜底（`_to_image_with_timeout`）
- 失败或未安装 → 自动改用 Pillow 绘制同数据的灰度图（`_fallback_multiomics_chart_png`）

所以**缺少 kaleido 不会导致应用起不来**，报告照常导出，只是图表从 Plotly 渲染退化为 Pillow 绘制。
HTML / PDF 报告不受影响。想恢复 Plotly 渲染效果才需要装 `kaleido>=1.0` 并配好 Chrome。

### 3. 后端重启后历史任务的 AI 问答失效

后端如果没用持久化存储，重启后旧任务的结果文件就找不到了，AI 会答"无法提供"。这是后端侧的事，前端无解。

### 4. 容器内 `.env` 与 `docker-compose` 的变量

前端同时支持「环境变量」和「本机 `.env` 文件」。Docker 部署时以 `docker-compose.yml` 里注入的环境变量为准；
虚拟环境部署时读 `.env` 文件。**两边都改了更保险**，配置读取优先级是：Streamlit Secrets → 环境变量 → `.env`。
